## 1. 已验证事实

1. 游戏是英文原版 PES6（32 位，SecuROM 壳），共 8 个文件，**无需注册表即可运行**（本机就没有 `KONAMIPES6` 注册表键，游戏正常运行）。→ B 机直接拷贝整个文件夹就能用（B 机系统差异【待验证】）。
2. `PES6.exe` 内嵌两个 Konami 官方联机域名（二进制字符串实测可见）：
   - `pes6gate-ec.winning-eleven.net` —— 登录/大厅网关
   - `we9stun.winning-eleven.net` —— STUN（NAT 检测）
3. 本机（A）出口公网 IP = `222.90.31.149`，与你所述 PPPoE 公网 IP 一致 → 基本排除运营商级二次 NAT。【已验证出口 IP；ikuai WAN 口是否直接持有该 IP，请你在 ikuai 界面确认一眼】
4. A 的 Windows 防火墙：专用配置文件 = **关闭**，入站当前不被拦截。【已验证】（B 机防火墙状态未知。）
5. A 当前 hosts 有两条 PES6 记录指向 `192.168.50.113`，而该地址上**没有任何相关服务在监听**（netstat 已查）。→ 这个状态下进 network 菜单必然连不上。无论选哪条路线，都要先改这两行 hosts（系统文件，由你改）。
6. A 实际是**有线以太网**接入（Intel I219-V，192.168.50.113，网关 192.168.50.1），不是 WiFi。【已验证，不影响方案】
7. 说明：我的命令执行沙箱 UDP 出网受限，此前一次"端口不通"的探测结果不可信、已作废。TCP 探测有对照组（members.3322.org:80 通），结论可用。

## 2. 游戏联机原理（决定方案骨架）

- PES6 的 network 菜单**不是局域网直连模式**，而是"登录大厅服务器"模式：【高可能，社区通识】
  1. 客户端先对 `we9stun` 指向的 IP 做 STUN 探测（UDP 3478，老式 RFC3489，带 CHANGE-REQUEST）做 NAT 检测；【待验证：端口与行为细节】
  2. 通过后再连 `pes6gate` 指向的服务器（TCP）登录、进大厅；【待验证】
  3. 实际比赛是**两台客户端之间 P2P UDP 直连**（客户端自己的 UDP 端口在 settings.exe 里可配，Auto 时为 5730~5739 一段；社区经典报错 `Unable to transmit using UDP port 573x` 就出在这一环节）。【高可能】
- 由此推论：
  - 大厅服务器在哪个国家基本不影响对战延迟（比赛是 A↔B 直连）。【高可能】
  - B 在手机热点 CGNAT 后，**只能当主动外连的客户端，当不了被连方**。【高可能】
  - A 侧要被 B 稳定连上，需在 ikuai 把对战 UDP 端口段转发到 192.168.50.113。【高可能】
  - **A 自己的 hosts 不要指向公网 IP**——ikuai 的 NAT 回环（hairpin）不保证支持。【待验证，社区常见坑】

## 3. 角色分工（由你的拓扑决定）

```
B(手机热点, CGNAT) ──只出站──> 公网 222.90.31.149 (ikuai, 每周变)
                                   │ 端口转发
                                   ▼
                     服务端所在内网(如 PVE LXC / A 机) ←── A(192.168.50.113, 有线)
```

- 服务端（大厅+登录）放 A 的内网侧；A、B 都作为客户端连它；A↔B 比赛走 P2P。

## 4. 三条路线

### 路线一：PES6VN 社区服（✅ 已核实在线，最快玩起来）
- 【已验证 2026-09-04】服务器 `103.82.27.235` 在线：ping 0% 丢包（A 实测 RTT≈324ms），TCP 10881、20200 开放（sixserver 系默认端口，与官网说明吻合）。
- 官方接入要求（取自官网 guide 接口，2025/2026 赛季版）：
  1. **两台电脑都改 hosts**（官网提供管理员权限脚本可自动写入）：
     ```
     103.82.27.235 pes6gate-ec.winning-eleven.net #PES6VN
     103.82.27.235 we9stun.winning-eleven.net #PES6VN
     ```
     注意：这个服把 `we9stun` 也指向自己，STUN 由服务端一并提供，**不需要**自己找 STUN。
  2. 双方安装**同一版** PES6VN 补丁（2025/26 全量版；Google Drive 主链 + MediaFire 备链，见官网指南页 https://pes6.online/huong-dan ）：
     - 解压覆盖游戏目录；把补丁内的 `KONAMI` 文件夹拷到 `C:\Users\<用户名>\Documents`；
     - 按系统位数运行补丁里的 Registry Key 文件（32/64）。
     - ⚠ Google Drive 国内直连不了，需代理；也可在 A 下载后把补丁包直接拷给 B。
  3. 进游戏 network 菜单 → 连接测试 → 注册/登录 → 大厅创建/加入房间对战。
- 延迟预期：大厅服务器在越南（RTT≈324ms【已验证】），大厅内操作会偏慢但可用；**比赛是 A↔B P2P 直连**，预期延迟远低于此（同城手机热点一般几十 ms）。【高可能，待实测】
- 不确定项【待验证】：注册方式（可能要经其 Facebook 群）、补丁文本语言（越南社区版）、服务器是否校验双方补丁版本一致。

### 路线二：自建私服（用你的 PVE，长期方案）
- 组件：开源 **Sixserver**（evo-league 项目，Python）+ MySQL，Docker 部署在 PVE 的 LXC/VM 里。老式 2009 年那套 GoalServer6/PESTooL 工具功能弱，不推荐做主线。【高可能】
- 端口（按项目默认配置，部署时以实际为准【待验证】）：TCP 10881（游戏）、20200/20201/20202（主服务/网络菜单/登录）、Web 界面 8190；STUN 需另行解决（UDP 3478）。
- hosts：A → LXC 内网 IP（如 192.168.50.33）；B → `222.90.31.149`。
- ikuai 转发：上述 TCP（+自建 STUN 时 UDP 3478）→ LXC IP；另加 `UDP 5730-5740 → 192.168.50.113`（对战 P2P 用）。
- 公网 IP 每周变：B 手动改 hosts；或 ikuai 配 DDNS + B 机用本地 DNS 代理（如 Acrylic）把 konami 域名别名到你的 DDNS 域名，实现自动跟随。【待验证方案】
- **最大坑（社区公认难点⚠）**：PES6 的 NAT 检测要求老式 RFC3489 STUN 行为（CHANGE-REQUEST / CHANGED-ADDRESS 语义）。不兼容的 STUN（包括很多现代 STUN）会让连接测试永远过不去。对策：优先找一个当前可用、回 MAPPED-ADDRESS 的公网 STUN 给两端共用【待验证】，不行就在 LXC 上自建双端口（3478+3479）老式 STUN（脚本我可以写好放本文件夹）。

### 路线三：虚拟局域网（兜底）
- ZeroTier / Radmin VPN 把 A、B 拉进同一虚拟网，服务端跑在 A 或 PVE，hosts 指虚拟 IP。
- 优点：完全绕开端口映射、hairpin、动态 IP 三个坑。缺点：两台都要装第三方软件+注册；流量走中继时延迟增加【待验证】。

## 5. 两台机器的 Checklist（以路线二为例）

| | A（主机侧） | B（客机） |
|---|---|---|
| 游戏 | 本文件夹直接运行 | 拷贝同一份文件夹（版本必须一致【高可能】） |
| hosts | 两行 → LXC 内网 IP | 两行 → A 的公网 IP（或 DDNS 方案） |
| 路由器 | ikuai 转发 TCP 10881/20200-20202、UDP 3478→LXC；UDP 5730-5740→192.168.50.113 | 无要求（热点只出站） |
| 其他 | settings.exe 的 UDP 端口保持 Auto 或固定后照此转发 | 文本文件须与 A 一致（社区说法：联机须英文文本【待验证】；本包 e_text 本就是英文） |
